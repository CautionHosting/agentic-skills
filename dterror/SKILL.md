# dterror error type design

**Every error type in this project uses dterror.** This skill is the
authoritative convention for writing typed errors, and it should be consulted
whenever you write or edit a function that returns `Result`, define or extend
an error enum or struct, or add `#[derive(thiserror::Error)]`. dterror is not
optional; treat its conventions (below) as the required shape for all error
types, not a suggestion.

This skill is a **companion to `convert-anyhow-to-thiserror`**, which already
documents how dterror 0.3.0 works mechanically (the derive, the generated
`{Error}Ctx` constructors, `.with_context(...)`, `#[source]`/`#[location]`/
`#[context]`). Read that skill for the mechanics; this one answers the design
questions that come up when authoring a new typed error:

1. Struct or enum — and in a struct error, where do shared vs variant-specific
   fields go (the `{Error}Kind` split)?
2. How do I pass references to `Ctx::new(...)`?
3. Why prefer `#[location]` + `#[source]` and avoid `#[from]`?
4. When is `#[context(borrow = T)]` worth it?

Naming convention used across this project:

```rust
use AddWidgetErrorCtx as Ctx;
```

every error gets a twin `{Error}Ctx` type generated by the derive, and call
sites import it as `Ctx` so the constructors read naturally.

## Struct or enum?

Decide by the **shape of the failure**, not by how many ways the function can
fail.

### Enum: multiple distinct failure modes

Use an enum when different failures carry **different messages and different
context fields**. This is the default for command entry points, which surface
several unrelated failure modes.

```rust
use dterror::{BoxError, CtxError, Location};

#[derive(Debug, thiserror::Error, CtxError)]
pub(crate) enum AddWidgetError {
    #[error("authentication required [{location:?}]")]
    EnsureAuthenticated {
        #[location] location: Location,
        #[source] source: BoxError,
    },
    #[error("prompt failed [{location:?}]")]
    PromptInput {
        #[context(borrow = str)] prompt_label: String,
        #[location] location: Location,
        #[source] source: BoxError,
    },
    #[error("failed to read config file '{path}' [{location:?}]")]
    ReadFile {
        #[context(borrow = Path)] path: PathBuf,
        #[location] location: Location,
        #[source] source: BoxError,
    },
    #[error("server returned failure status [{location:?}]")]
    ServerFailure {
        #[location] location: Location,
        #[source] source: BoxError,
    },
}
```

The dterror derive emits one **per-variant constructor** on the Ctx twin:

```rust
Ctx::prompt_input(&label)             // -> PromptInput
Ctx::read_file(&path)                 // -> ReadFile
// variants with no context fields are auto-constructible with no args:
Ctx::server_failure()
```

The constructor takes each context field in declaration order (the
`#[location]`/`#[source]` fields are populated by the machinery, not passed).

### Struct: shared fields on the error, variant data on a `{Error}Kind`

Use a struct when the failure is one shape parameterized by a category — every
variant shares `#[source]`, `#[location]`, and any other context all variants
carry. The split is fixed: **shared fields go on the struct** (`#[source]`,
`#[location]`, plus whatever else is common), while **information specific to
individual variants goes on a separate `{Error}Kind` enum**. Keep a single
message template on the struct, interpolating `{kind:?}`.

#### Variants with no data of their own: plain kind enum

When the variants are bare categories, a plain `Copy` enum is enough; it rides
along as an owned context field.

```rust
use dterror::{BoxError, CtxError, Location};

#[derive(Debug, Clone, Copy, PartialEq)]
pub(crate) enum ComputeSizeErrorKind { Metadata, Iterate, Calculate }

#[derive(Debug, thiserror::Error, CtxError)]
#[error("failed to compute size of '{path}' ({kind:?}) [{location:?}]")]
pub(crate) struct ComputeSizeError {
    kind: ComputeSizeErrorKind,
    #[context(borrow = Path)] path: PathBuf,
    #[location] location: Location,
    #[source] source: BoxError,
}
```

The dterror derive emits a **single `new(...)` constructor** on the Ctx twin,
taking the context fields in declaration order:

```rust
Ctx::new(ComputeSizeErrorKind::Metadata, &path)
```

#### Structs whose failure modes lack a source: `Option<BoxError>`

The kind enums above have no notion of a source, so they assume every
failure delegates to the caller-supplied `#[source]` on the struct. When one of
your failure modes is source-less — a *domain* failure, e.g. a file exists but
has the wrong shape — use `#[source] source: Option<BoxError>` on the struct.
The derive detects the `Option` and wraps the captured source in `Some(...)`; a
hand-built source-less variant just sets `source: None`. You can make the
intent explicit with the `#[context(option)]` marker on the source field. This
works identically with a plain kind enum or a `FromContext` kind.

```rust
use dterror::{BoxError, CtxError, Location};

#[derive(Debug, Clone, Copy, PartialEq)]
pub(crate) enum ReadPcrsFileErrorKind { Read, Incomplete }

#[derive(Debug, thiserror::Error, CtxError)]
#[error("failed to read PCRs file at {path} ({kind:?}) [{location:?}]")]
pub(crate) struct ReadPcrsFileError {
    #[context(borrow = str)] path: String,
    kind: ReadPcrsFileErrorKind,
    #[location] location: Location,
    #[source] source: Option<BoxError>, // Incomplete has no underlying error
}
```

Call sites: the source-bearing kind routes through `with_context`
(`source` is auto-wrapped in `Some`); the source-less kind is built by hand
with `source: None`:

```rust
r.with_context(Ctx::new(ReadPcrsFileErrorKind::Read, path))?;

// source-less domain failure: path stays on the error, source is None
return Err(ReadPcrsFileError {
    path: path.to_string(),
    kind: ReadPcrsFileErrorKind::Incomplete,
    location: std::panic::Location::caller(),
    source: None,
});
```

This is what lets a struct keep a **whole-error shared context** (the `path`)
even when one specific failure mode has no underlying source — the shared field
never disappears, it just carries `source: None` on that variant.

#### Variants with their own data: `FromContext` kind

When different variants carry different fields (a path here, a line number
there), put those fields on the kind and derive `dterror::FromContext` on it.
The derive generates a `{Kind}Ctx<'ctx>` with one `snake_case` constructor per
variant (borrowed fields take `&'ctx Target` directly) plus
`impl From<{Kind}Ctx<'_>> for {Kind}`. Mark a kind field
`#[context(borrow = T)]` to hold a reference in the Ctx and materialize the
owned value only on the error path. The error's kind field then names the kind
Ctx as its `#[context(from = ...)]` target:

```rust
use dterror::{BoxError, CtxError, FromContext, Location};

#[derive(Debug, FromContext)]
pub(crate) enum LoadConfigErrorKind {
    ReadFile {
        #[context(borrow = Path)] path: PathBuf,
    },
    Parse {
        #[context(borrow = Path)] path: PathBuf,
        line: usize,
    },
    Missing,
}

#[derive(Debug, thiserror::Error, CtxError)]
#[error("failed to load config ({kind:?}) [{location:?}]")]
pub(crate) struct LoadConfigError {
    #[context(from = LoadConfigErrorKindCtx<'a>)] kind: LoadConfigErrorKind,
    #[location] location: Location,
    #[source] source: BoxError,
}
```

Any lifetime written in the `from =` target is bound to `'ctx`. If no kind
field borrows (or names a lifetime), `{Kind}Ctx` has no lifetime parameter and
the target is written bare (`#[context(from = ComputeSizeErrorKindCtx)]`).

Call sites build the kind through its Ctx and pass it to the error's `new`:

```rust
// &path is only converted into an owned PathBuf if the error actually fires
r.with_context(Ctx::new(LoadConfigErrorKindCtx::read_file(&path)))?;
// unit variants get a zero-argument constructor:
r.with_context(Ctx::new(LoadConfigErrorKindCtx::missing()))?;
```

On the Ok path nothing is allocated for borrowed kind fields (the Ctx holds
references); on the Err path `from_context` converts `{Kind}Ctx` back into the
owned kind via `.into()`.

For a named-field struct the `#[error(...)]` attribute goes on the struct
itself, not on a field. The generated `{Error}Ctx<'ctx>` derives nothing by
default; you opt into traits with the container-level `#[context(derive(...))]`
(e.g. `#[context(derive(Debug))]`). If your code needs the Ctx to be `Clone`,
`Debug`, `PartialEq`, or anything else, list it there — everything the Ctx
stores must implement the requested traits.

### Heuristic

- Can every failure be described with **one message template** plus a category
  field? Use a struct (+ `{Error}Kind`): shared fields on the struct,
  variant-specific data on the kind (plain enum when bare, `FromContext`
  derive when the variants carry fields).
- Do different failures need **different messages and different context
  fields**? Use an enum.
- A struct collapses distinct per-variant messages into one `({kind:?})`
  template. Prefer an enum when those messages are themselves user-facing
  guidance (e.g. "path has no parent") rather than a generic category — a
  struct wins when the shared context (a `path`, a key name) matters more than
  the per-variant wording.
- **Whole-error shared context** philosophy: when every failure is about the
  same entity (a `path`, a key), hoist that field to the struct (or put it on
  every enum variant) so it is present regardless of which failure fires —
  even a source-less variant keeps it, with `source: None` (`Option<BoxError>`).
- Convert a struct to an enum later only when a genuinely new failure shape
  (new context field / message) appears. Prefer the minimal form that models
  the failures accurately.
- **Hard constraints on the struct path:** `#[derive(CtxError)]` accepts only
  structs with named fields, and requires at least one *context* field — a
  field marked `#[source]`/`#[from]` or `#[location]` does not count. An error
  that carries nothing but the boxed source (plus location) cannot be a struct
  error at all; it must be an enum, even with a single variant.
- Context fields come first in the struct, before `#[location]`/`#[source]`,
  to match constructor argument order and keep the message template readable.

## Passing references to the constructors

Context fields are declared **owned** (`PathBuf`, `String`, `ErrorKind`).
The generated `Ctx` constructors take `impl Into<FieldType>`, so you can hand
over a reference at the call site without moving the value out of scope — the
owned value is only materialized if the error actually fires.

```rust
fn compute_size(root: &Path) -> Result<u64, ComputeSizeError> {
    use ComputeSizeErrorCtx as Ctx;

    // pass &root; path is not moved or cloned on the success path
    let entries = std::fs::read_dir(root)
        .with_context(Ctx::new(ComputeSizeErrorKind::Metadata, root))?;
    ...
}
```

Rules of thumb:

- Pass **by reference** (`&Path`, `&str`, `&[u8]`) when the callee can proceed
  without owning the value until the error fires — this is the common hot loop
  case.
- Pass **by value** only when the caller already owns the value and has no
  further use for it (e.g. the value is being consumed by the operation anyway).
- A plain field declaration (`#[context]` or implicit owned context) stores the
  owned value. A `#[context(borrow = T)]` field stores a reference in the Ctx
  and reconstructs the owned value via `.into()` only on the error path — see
  the borrow section below.

## Prefer #[location] + #[source]; avoid #[from]

### `#[source]`, never `#[from]`

Every fallible variant carries exactly one `#[source]` field, always typed as
dterror's alias:

```rust
#[source] source: BoxError, // dterror::BoxError = Box<dyn std::error::Error + Send + Sync + 'static>
```

`#[from]` is **avoided** for two compounding reasons:

- `#[from]` generates a blanket `From<E> for Error`. Combined with
  `.with_context(Ctx::...)`, the compiler cannot disambiguate between the
  automatic `From` conversion and the context constructor, producing E0282 /
  E0283 inference conflicts.
- `#[from]` cannot capture `#[location]` (the location is set by the caller via
  `#[track_caller]`), and it cannot supply context fields, so it can never
  produce as informative an error as the Ctx constructors.

Route error wrapping explicitly instead — always through the Ctx constructor,
which sets `#[location]` via `with_context`'s `#[track_caller]` machinery. A
variant with a `#[source]` field is always constructible, even with no context
fields (zero-argument constructor); only source-less variants are built by
hand:

```rust
some_fallible_call().with_context(Ctx::server_failure())?;

// source-less variant (domain failure): built by hand, fully qualified caller
return Err(FooError::NotFound { resource_id, location: std::panic::Location::caller() });
```

Source-less variants are the reason to type the `#[source]` field
`Option<BoxError>` in a **struct** error (see the optional-source subsection
above): the derive wraps the captured source in `Some(...)`, while a source-less
kind is hand-built with `source: None`. This keeps the shared whole-error
context (e.g. `path`) on every failure even when one has no underlying error.

#### Wrapping `anyhow::Error` and other non-`Error` sources

`with_context`'s source bound is `Old: Into<BoxError>` (not
`Old: std::error::Error`). Every `Error + Send + Sync` value qualifies via
std's `From<E>` blanket, and so does `anyhow::Error` — which deliberately does
**not** implement `std::error::Error`, but converts into exactly a `BoxError`
via `anyhow::Error::into_boxed_dyn_error`. So a `#[source] source: BoxError`
field takes an `anyhow` source directly, with no `.map_err(...)` fallback at
the call site:

```rust
// read_config() -> Result<String, anyhow::Error>
read_config().with_context(Ctx::server_failure())?;
```

Only reach for `.map_err(...)` when the source is genuinely not convertible
into a `BoxError` (e.g. a `StatusCode` that is not `Send + Sync + 'static` or
an error value you must reshape first). Prefer `.with_context(...)` everywhere
else so the location and context are captured.

Even when a variant is produced at exactly one call site, use
`.with_context(...)` rather than `#[from]` so the location and any context
field are captured. The `#[error()]` message must not interpolate the source;
`#[source]` is surfaced by the error chain.

### `#[location]`

Every struct and enum variant carries:

```rust
#[location] location: Location, // dterror::Location = &'static std::panic::Location<'static>
```

- `.with_context(Ctx::...)` fills it automatically (the Ctx constructor is
  `#[track_caller]`); you do not pass it.
- Hand-built (source-less) variants set it explicitly with
  `std::panic::Location::caller()`. The alias cannot be used for the call
  itself — `Location::caller()` through `dterror::Location` does not compile,
  so write the std path fully qualified (and do not also import
  `std::panic::Location`, which would collide with the dterror import).
- End the `#[error()]` message with the location so display includes it:

```rust
#[error("failed to clean up files [{location}]")]
```

## #[context(borrow = T)] to avoid cloning or moving

By default a context field is stored owned in the Ctx, so the caller's value
is moved or cloned at the `Err(...)`/`.with_context(...)` construction — even
on the success path where it is never used.

`#[context(borrow = T)]` stores a **reference** in the Ctx and only calls
`.into()` to reconstruct the owned field if the error actually fires.

```rust
#[context(borrow = Path)] path: PathBuf,
#[context(borrow = str)] prompt_label: String,
```

`T` is the reference target (`str`, `Path`, `[u8]`, ...) and the owned field
must implement `From<T>`. Call sites then hand over a reference:

```rust
// path: &Path -> Ctx holds &Path; PathBuf built only on error
Ctx::read_file(&config_path)
```

Use `#[context(borrow = T)]` when **both** hold:

1. The call site holds a reference it can hand over and does not need to keep
   owning (so passing `&value` loses nothing).
2. The success path is hot enough (or the value large/expensive enough to
   clone) that avoiding the clone/move is worthwhile.

Otherwise a plain owned context field is fine — e.g. `ErrorKind` is a small
`Copy` enum and is always passed by value:

```rust
Ctx::new(ComputeSizeErrorKind::Metadata, &path)
//        ^ maybe #[context]; an ErrorKind is Copy, so no borrow needed
```

Note: borrowing in the Ctx means the reference must outlive the
`.with_context(...)` call — which is guaranteed because the Ctx is consumed
immediately. Do not retain a `Ctx` beyond its single use.

## Checklist

- [ ] Struct for one failure shape (+ `{Error}Kind`); enum for distinct modes.
      Struct errors use named fields and carry at least one context field
      (source/location don't count) — otherwise it must be an enum.
- [ ] In a struct error: shared fields (`#[source]`, `#[location]`, other common
      context) on the struct; variant-specific data on the kind — plain `Copy`
      enum when bare, `#[derive(FromContext)]` with `#[context(borrow = T)]`
      kind fields and `#[context(from = KindCtx<'a>)]` on the error when the
      variants carry fields.
- [ ] Context fields first, then `#[location]`, then `#[source]`.
- [ ] Exactly one `#[source]` field, typed `dterror::BoxError` (or
      `Option<dterror::BoxError>` when some failure modes have no source); no
      `#[from]`.
- [ ] `#[location] location: dterror::Location` on every struct/variant;
      `#[error(... [{location}])]` so display includes it.
- [ ] A struct with any source-less failure mode types its source
      `Option<BoxError>` (optionally `#[context(option)]`): source-bearing kinds
      route through `with_context` (auto-wrapped in `Some`), source-less kinds
      are hand-built with `source: None` — keeping the shared whole-error
      context on every failure.
- [ ] Ctx traits via `#[context(derive(...))]` on the error; everything the Ctx
      stores must implement the requested derives.
- [ ] Wrapping goes through `.with_context(Ctx::...)` — zero-arg constructor for
      context-less variants; only source-less variants are built by hand.
- [ ] Reference args (`&Path`, `&str`) to `Ctx::new(...)`/variant constructors;
      only move owned values the caller is discarding.
- [ ] `#[context(borrow = T)]` only when the call site holds a reference AND the
      success path is hot enough to justify skipping the clone/move.
- [ ] `use {Error}Ctx as Ctx;` naming convention at the call site.
